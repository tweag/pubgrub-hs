# The benchmark problem set: one problem per line, "<package> [version-range]".
# Blank lines and #-comments are ignored. Quote nothing — the range is the rest of
# the line.
#
# Why these. Constraining a package to an OLDER release is what forces conflicts:
# the old bounds have to be reconciled against everything else. Unconstrained
# popular packages mostly do not conflict at all, which is how a benchmark set can
# report a search improvement as worthless.
#
# Keep the three kinds separate when reading results. Two problems measure index
# throughput, three measure search on an unsatisfiable problem, and one measures
# search on a satisfiable one. A change that helps only one kind is not a change
# that helps. See docs/benchmarking.md.

# --- index throughput: little or no search ---
vector                  # 39 decisions, 0 conflicts. The floor.
pandoc                  # 270 decisions, 1 conflict. Reads dominate, so it cannot show
                        # a search win. Regressions in read count show up here first.

# --- real search, all three currently UNSAT for both solvers ---
conduit <1.3
lens <4
aeson <2                # the deepest resolution chain in the set

# --- search on a satisfiable problem ---
yesod                   # 827 decisions, 11 conflicts, ~2.6 s. The only sat problem in
                        # the set with real search in it: vector and pandoc resolve
                        # almost straight through. Keep it: a problem nobody re-runs
                        # is a problem whose regressions nobody sees.
